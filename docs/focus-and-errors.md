# Focus, errors and lost work

An action that removes, replaces or disables the control that has focus drops focus to the page, and a keyboard reader starts over from the top. A request error that disappears while its retry runs takes its button with it. A draft held by a component that a view switch unmounts is lost without asking. The shared parts in `src/ui` handle each case once; this page says which one to reach for.

`scripts/policies/check-focus-handoff.ts` rejects the mechanical cases (a pending button disabled without `pendingLabel`, a field disabled while typing, and the rest listed in its header). The choices below are the ones it cannot make.

## Where focus goes when a control leaves

| When                                                                                                       | Use                                                                                                                                                                                                                                                                   | Example                                                         |
| ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Anything inside a `Dialog`, `SideSheet` or `PopoverSurface`                                                | Nothing: the surface's net (`catchLostFocus`) hands lost focus to its first control                                                                                                                                                                                   | `src/ui/Dialog.tsx`, `src/ui/PopoverSurface.tsx`                |
| Pressing a control disables it (a vote, a reset, a pager at its end)                                       | `disabled` plus `accessibleWhenDisabled`, so it keeps focus and swallows presses; a request it starts is `pendingLabel` instead                                                                                                                                       | `ResetFiltersButton.tsx`, `src/components/Table/TablePager.tsx` |
| A synchronous change outside a dialog removes the pressed control                                          | `keepFocus(commit, target)`                                                                                                                                                                                                                                           | `SelectItemsStep.tsx`                                           |
| A row leaves its list (remove, unpin, unlink), now or when data drops it later                             | `focusNeighborOnLeave(fallback)` as the control's ref, `data-row` on each row: the next row's control at the same place, else the previous row's, else `fallback`                                                                                                     | `src/ui/MultiSelectCombobox.tsx`                                |
| Data removes the control later and nothing takes its place                                                 | `passFocusOnLeave(target)` as the control's ref                                                                                                                                                                                                                       | `src/components/Nav/Account.tsx`                                |
| A card leaves after a refetch and the neighbor's link, not the same control, should take focus             | `passFocusOnLeave` on the card, its target `neighborRowControl(card, card)`'s link, else the list's region                                                                                                                                                            | `ProDashboard/components/DashboardCard.tsx`                     |
| A control swaps for its counterpart (Edit and Done)                                                        | One element whose label and action change, so it keeps focus; never two components that unmount and mount                                                                                                                                                             | `EditDoneButton` in `DashboardActionButtons.tsx`                |
| A Try again outside a dialog leaves once its read succeeds                                                 | `focusRegionOnLeave` as its ref: the nearest `tabIndex={-1}` region, else `<main>`                                                                                                                                                                                    | `ProCardStatus.tsx`, `RetryButton` in `src/ui/Status.tsx`       |
| Something that loads later replaces the control                                                            | `takeLostFocus` as the replacement's ref                                                                                                                                                                                                                              | `src/components/Search/index.tsx`                               |
| A loading state replaces the control that started the load, or what loads replaces it inside a shared part | `focusRegionOnLeave` as the control's ref, inside a `tabIndex={-1}` region that survives the swap and an empty result                                                                                                                                                 | `Token/TokenDeferredPaginationControls.tsx`                     |
| A pager's next page loads                                                                                  | Keep the previous page on screen (`placeholderData`), so the pager stays mounted; a skeleton only on the first load                                                                                                                                                   | `ProDashboard/hooks/useMyDashboards.ts`                         |
| The action's own control unmounts at an edge (a pager's Next on its last page, a rail arrow at the end)    | Keep it rendered and disabled (the second row); if it must go, `keepFocus(commit, target)` with the control that moves back                                                                                                                                           | `src/components/Table/TablePager.tsx`                           |
| A dialog closes                                                                                            | Nothing by default: its opener, else `<main>`. Pass `finalFocus` for a nearer target, and always when another dialog opened it (Quick add's "All card types…" opens Add card): the first dialog's opener, recorded when it opened, never a control a breakpoint hides | `DashboardCard.tsx`, `DeletePortfolioButton.tsx`                |
| A confirm's success removes the control that opened it                                                     | `finalFocus` pointing at the neighbor, set in the confirm's `onSuccess`                                                                                                                                                                                               | `ProjectsGrid.tsx`                                              |

Inside a dialog or popover, a handoff that only reproduces the net is redundant, but a row's neighbor is nearer than the net's first control; outside one, a control that removes itself always hands focus on. Focus never lands on `<body>`, and `<main>` (`pageContent()`) is the last resort, not the default target.

Each recipe above is a call or two at the site, so it stays inline: a dismiss's `keepFocus(dismiss, pageContent)`, a row delete's confirm with `finalFocus`, a mutation's own Try again, an inline rename, a field's clear ×. A part that only wraps one of them adds an API without removing a mistake. A shared part earns its place when copies drift or carry their own look, as `focusNeighborOnLeave` and the status parts' `retry` do. The raw `Ariakit.Dialog`s in the `raw-dialog-surface` exceptions (`check-design-tokens.mjs`) wire `catchLostFocus` themselves; each exception says why it is not a `Dialog`.

A dialog records the control that opened it, and a click inside a dialog focuses the pressed button first, as Chrome does, so Safari and Firefox return focus to the right place too. Never read `Ariakit.useDialogContext()` to find "the dialog": inside a `TabPanel` it returns the panel's store. Use what the surface provides (`DialogCancelButton`, `DialogBackButton`, `useDialogLeave`).

A part decides what to render from its props, never from store state its own render sets (Ariakit's `anchorElement`, `disclosureElement`, `popoverElement`). The element registers itself when it mounts, that update renders the part again, a different branch mounts a new element that registers in turn, and React stops with "Maximum update depth exceeded". `Hovercard` reads whether its anchor is a button from `render`, so the server and the first client render agree too.

## Errors and retries

| When                                                 | Use                                                                                                                                         | Example                                                                        |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| A read fails with nothing to show                    | `queryReadFailed(query)` checked before loading, so a retry from an error keeps the error and its button on screen                          | `src/utils/query.ts`, `src/auth/useSubscribe.tsx`                              |
| A refetch fails with data on screen                  | `queryRefreshFailed(query)`: keep the data and add a quiet notice with its Try again (`ProCardRefreshFailed`), never the error in its place | `src/utils/query.ts`, `ProCardStatus.tsx`                                      |
| A mutation on the page invalidates a list            | `queryRefreshFailed(query)` notice above the list (`InlineStatus` with `retry`): its rows may predate the change the reader just made       | `BannersListView.tsx`, `TrustedByAdminView.tsx`                                |
| Its Try again runs                                   | The same button with `pendingLabel="Retrying…" pending={query.isFetching}`                                                                  | `ProCardStatus.tsx`                                                            |
| An action fails                                      | One nullable error state, set in `onError` and cleared on success or an edit; never `mutation.error`, which clears when a retry starts      | `src/containers/Account/CancelSubscriptionModal.tsx`                           |
| A confirm runs an action                             | `ConfirmActionDialog`: it owns the error and keeps it through a retry                                                                       | `src/ui/ConfirmActionDialog.tsx`                                               |
| An accepted action changes data (remove, save local) | The mutation's own `onSuccess`, which runs after the view unmounts                                                                          | `deletePortfolioWithNotifications` in `src/containers/DeFiWatchlist/index.tsx` |
| The dialog is gone when the request settles          | A toast, only then (`if (!ref.current?.isConnected) toast…`)                                                                                | `src/components/ReportIncorrectData/index.tsx`                                 |

### Error copy

- Say what failed, as the reader would name it: "Couldn't load your dashboards.", "Couldn't save the chart." Sentence case, ending with a period.
- Add "Try again." only where nothing beside the message offers a retry (a toast, a line with no button). A Try again button already says it.
- Never "Failed to …", "… could not be loaded", "Something went wrong", "Oops", "Error:", first person, or "Please". A sign-in gate reads "Sign in to save dashboards."
- A thrown `Error` message follows the same rules: callers pass it to toasts and notices, so it is reader copy wherever it may surface.
- Show a server's message only where the API writes it for readers. A generic fetch error's `message` ("Failed to fetch", a status text, an HTML page, a server code) never reaches the screen; the site writes its own line.
- A failed request throws an `HttpError` (`handleSimpleFetchResponse`, and `ArticleApiError`, `AuthorApiError` and `DashboardError`, which extend it). Its `message` is for logs. Its `reason` is the text the API wrote in its JSON `error` or `message`, kept only on a 4xx, because a 5xx body says nothing the reader can act on.
- Show a failure with `httpErrorMessage(error, "Couldn't save the article.")`: the reason when there is one, else the site's line. `ConfirmActionDialog` takes that line as `errorMessage`. Show `error.message` as it is only when every error that can reach the site is reader copy: a typed client check (`UploadError` under 500, `CustomDataParseError`), a function that turns each failure, the network one included, into "Couldn't …", or an SDK that writes for buyers (Stripe).
- `scripts/policies/check-status-parts.ts` refuses the banned phrasings (`error-copy`) and `x instanceof Error ? x.message : …` or `getErrorMessage(…)` outside console calls (`raw-error-message`) in client code. Server routes and build scripts are not scanned: their messages go to logs and API consumers.

Never call `mutation.reset()` while a newer request may be pending: it detaches the running request and unlocks a pending dialog.

A retry that hides its error removes the button that has focus, never shows its pending label, and moves the layout twice. Keep the error until the retry succeeds.

A failed read's Try again comes from the status part: pass the query as `retry` to `PanelStatus`, `SurfaceBodyStatus` or `InlineStatus`, and the part draws it with the focus handoff. Place one by hand only when it hands focus somewhere better (a search field that stays).

`scripts/policies/check-status-parts.ts` fails a retry gated on a query's `isError`, `isLoadingError` or `error`, a loading test of the same query placed before its failed read, and a read's Try again placed by hand inside a status part.

`ConfirmActionDialog`'s `onSuccess` and a `mutate()` call's own callbacks are skipped once the dialog or component has gone. Put only view work there: closing, focus, a redirect that only makes sense while the page is open. Work that belongs to the accepted action goes in the mutation's `onSuccess`, and it names its entity from the mutation's variables, never from state read at settle time.

## Validating a form

A submit button that stays disabled until the input is valid hides what is wrong: the reader sees a dim button, and the reason, if any, sits somewhere else. Pressing it says what is wrong instead, beside the field that needs fixing.

| When                                                    | Use                                                                                                                                                                                                                             | Example                                                  |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| A form has fields to check                              | Derive each error from the values during render; one `submitted` state decides whether they show. The submit stays enabled                                                                                                      | `src/components/NewPortfolioDialog.tsx`                  |
| The reader submits with an error                        | `showFieldErrors(form, () => setSubmitted(true))` from `src/ui/focus.ts`: it renders the errors, then focuses the first invalid field so a screen reader reads it with its error                                                | `src/components/Newsletter/NewsletterSignup.tsx`         |
| A field or a set of choices shows its error             | `Field` / `FieldGroup` (`src/ui/Field.tsx`): the error under the control in `body-sm text-error`, `aria-invalid` and `aria-describedby` wired; never `text-data-down`, which is for numbers                                     | `src/ui/Field.tsx`                                       |
| The reader fixes a field after a submit                 | Nothing: the error is derived from the values, so it updates as they type and clears once the value is valid                                                                                                                    | `src/components/NewPortfolioDialog.tsx`                  |
| An email field                                          | `emailError(value)` from `src/utils/email.ts`                                                                                                                                                                                   | `src/containers/Account/Team/InviteMemberModal.tsx`      |
| A check answers "will this work?" while typing          | Show it live with `Field live`, which announces it: a formula that parses, an embed URL that resolves, a name already taken. Never a live "you haven't finished" error                                                          | `src/containers/Articles/editor/EmbedPicker.tsx`         |
| The server rejects a value (a taken name, a wrong code) | The same `Field` error, from the request's error state, cleared on the next edit. Set it through `showFieldErrors` so focus lands on the field and its error is read out; the rest of the request errors stay in `InlineStatus` | `src/auth/VerifyEmailDialog.tsx`                         |
| The control a check needs is loading or failed to load  | A gate, not an error: the submit waits (`pendingLabel`) while it loads, and stays disabled beside the failure and its Try again. An error under a control the reader cannot use, or under nothing, is a dead button             |
| An inline rename is cleared to blank                    | Keep the old name, as Finder and Figma do; no error. A rename dialog with its own Rename button shows "Enter a … name." instead                                                                                                 | `src/containers/LlamaAI/projects/ProjectSessionItem.tsx` |

- Every `<form>` takes `noValidate`; `required`, `type="email"` and `min` stay for their semantics and mobile keyboards, never for the browser's bubble (`scripts/policies/check-form-validation.ts`).
- `noValidate` also turns off what `min`, `max`, `minLength`, `pattern` and `step` enforced; they only shape the picker or keyboard now. Each one needs a derived error that says the same thing (a date before the dataset's first day, a future day, a count below the floor), with a test for both sides and the boundary.
- A submit may still disable for something that is not the input: a request running (`pendingLabel`), a security check that has not answered, a cooldown, nothing to act on, a missing permission. Its reason shows in visible text.
- Typing a name to confirm a destructive action is friction on purpose, not validation: its button stays disabled until the name matches.
- An empty chat composer disables its send arrow, as every chat does.
- The submit pattern (`submitted` state, `preventDefault`, `showFieldErrors`, `noValidate`) stays inline at each form. There is no shared `Form` part: a reset after success, a server refusal and a region check each differ per form, and each would need its own escape hatch in it.
- Copy: "Enter …" for missing text, "Choose …" for a missing pick, "Enter a valid …" for a malformed value; one sentence, no "Please".

## Inside a dialog

Pending states, errors and outcomes stay in the dialog. The surface and its parts are described in the `src/ui/Dialog.tsx` header.

| When                                               | Use                                                                                                                                                                                                 | Example                                                                   |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| A button starts a request                          | `pendingLabel="Saving…"` with `pending` on that button: spinner and label, focus kept, presses ignored; never a status line elsewhere                                                               | `src/ui/Button.tsx`                                                       |
| A check decides whether an action may run          | Render the content at once; the action's button waits with `pendingLabel="Checking…"`, never a loading screen that grows into the layout                                                            | `src/containers/Account/DeleteAccountCard.tsx`                            |
| That check fails                                   | Its error inline, and the same button becomes "Try again"                                                                                                                                           | `src/containers/Account/DeleteAccountCard.tsx`                            |
| A request fails                                    | `InlineStatus variant="error"` at the end of the body, right above the footer; field errors sit under their field                                                                                   | `src/components/ReportIncorrectData/index.tsx`                            |
| A dismissed banner or strip leaves with its button | `keepFocus(dismiss, pageContent)`: nothing nearer survives, so `<main>` takes focus. A store that re-renders a task later (local storage) takes `passFocusOnLeave(pageContent)` as the button's ref | `src/components/Announcement.tsx`, `LlamaAI/components/FreeUsageNote.tsx` |
| An error offers a retry                            | A failed read passes its query as the status part's `retry`; an action's retry is a small secondary `Button` ("Try again") in `action`, never an underlined link                                    | `src/components/AddToDashboard/AddToDashboardModal.tsx`                   |
| A consequence or blocker needs saying              | `InlineStatus variant="warning"` for consequences, `variant="error"` for blockers; one sentence, or a list for several                                                                              | `src/components/ReportIncorrectData/index.tsx`                            |
| A button is disabled for a reason other than input | Its reason in visible text (the footer's leading slot or a field hint), never only in `title=` or a tooltip. Invalid input never disables a submit; see "Validating a form"                         | `src/containers/Account/PasswordResetModal.tsx`                           |
| A new step or a success step appears               | `autoFocus` on its first field or its action                                                                                                                                                        | `src/components/ReportIncorrectData/index.tsx`                            |
| The action succeeds                                | A success step: the header title names the outcome, one `body-sm text-secondary` description says what happens next, one primary action                                                             | `src/components/ReportIncorrectData/index.tsx`                            |

- An error `InlineStatus` inside a dialog scrolls itself into view when it appears; callers never scroll to it. On pages it never scrolls.
- A success step never keeps the form, a disabled "Created" button, a tinted box or a large status icon.
- Never a tinted callout with its own type size: warnings and blockers are `InlineStatus` at the description's `body-sm`.
- Never toast while the dialog is open, success included; a toast appears only once the dialog is gone (the last row under "Errors and retries").
- A non-control that takes focus (`tabIndex={-1}`: a list, a step, a status line) shows the global focus ring; never hide it with `outline-hidden`.

## Lost work

- A draft lives in the component that stays mounted for the whole edit. A view switch inside a dialog (a detail view, a step, a tab) hides the editor instead of unmounting it, or lifts the draft above the switch.
- `DialogDiscardGuard when={dirty}` turns Escape, the ×, Cancel, Back and guarded steps into one "Discard?" question. Dirty means the draft differs from what the opening started with; opening a saved item without changing it is not dirty.
- Every exit goes through the surface: `DialogCancelButton` and `DialogBackButton` ask the guard and honor `pending`, and a step or tab switch that drops work calls `useDialogLeave()`. A plain `onClick={goBack}` skips the question.
- A pending request that cannot be canceled passes `pending` to the dialog, which locks every exit without asking.
