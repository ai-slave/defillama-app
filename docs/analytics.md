# Analytics

Product analytics go to Umami. `src/utils/analytics/umami.ts` sends events, `src/utils/analytics/experiment.ts` assigns and reports A/B experiments, and `src/pages/_app.tsx` loads the tracker and identifies signed-in users. Feature code sends through these helpers.

## Where the work goes

| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Count a click that needs no logic                                                       | `data-umami-event="<name>"` on the element, plus `data-umami-event-<key>` for each property; the tracker sends it on click                                                                                       | `export-csv` in `src/components/ChartExport/ChartPngExportButton.tsx`                              |
| Send an event from code                                                                 | `trackUmamiEvent(name, data)`                                                                                                                                                                                    | `llamaai-daily-brief-open` in `src/containers/LlamaAI/dailyBrief/HomeDailyBrief.tsx`               |

## Checks

- **Names are a contract:** event names, property keys, experiment ids and metric strings feed Umami reports and the experiment rollup. Renaming or removing one breaks a report, so it needs the report owner's agreement.
- **No personal data:** an event or `data-umami-event-<key>` never carries what identifies a reader: an email, a name they typed, a wallet address or free text they wrote. Count the action without the value. The opaque account id is the one exception, since `useUmamiIdentityTracker` already links it. Public entity names, such as a protocol, an exchange or an author byline, are not personal data.
- **The tracker loads late:** `_app.tsx` loads it with `lazyOnload`. `trackUmamiEvent` silently drops an event sent before then and never throws.
- **Local sends nothing:** the tracker only sends from the hosts in `data-domains` (`src/containers/Investors/umamiScript.ts`), so localhost and preview deployments report no events. Prove an event with a test.
- **The site cohort rides along:** `addABTag` adds the global A/B group as Umami's `tag` on every payload through `window.umamiABBeforeSend`. An event needs no group field for a site-wide comparison.
- **One experiment tracker:** experiments report through `experiment.ts`, which already queues until the tracker loads, dedupes exposure under `experiment-exposure:<id>` in session storage, and falls back to memory when storage is blocked. Never add a second queue, storage key or dedupe.
- **Ids are registered:** `ExperimentId` only accepts keys of `EXPERIMENTS`, and `experiment.test.ts` checks each id against the pattern the rollup accepts.
- **Assignment is deterministic:** `getExperimentVariant` hashes the experiment id with the unit id, so a unit gets the same arm on every page and each `visitor` or `user` experiment splits independently. `site` experiments share one cohort, so they are not independent of each other.
- **Missing assignment:** `readExperimentVariant` returns `null` when the page set no arm, such as on hosts outside the A/B cookies, and the CSS then shows A. Skip tracking for `null` unless the experiment counts those visitors as A on purpose.
- **Expose only who can see it:** send the exposure where the arms differ for this visitor. A hidden layout, a closed drawer, a viewport the test excludes or an ineligible account is not an exposure.
